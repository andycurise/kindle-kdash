# kdash 架构设计文档 (Architecture)

## 1. 架构演进与设计哲学

在早期版本中，kdash 曾尝试在 Kindle 设备本地直接运行 Go 语言编译的原生 ARM 二进制。然而实践中遇到了一系列棘手的硬件与系统瓶颈：
- **内核版本极低**：Kindle Paperwhite 2 (PW2) 固件基于 Linux 2.6.31 内核，缺少 modern Linux 系统调用（如 `epoll_pwait` 等），需要打补丁修改 Go 运行时；
- **内存受限与 OOM**：Kindle 内存紧张，当使用 Freetype 加载大号中文字体和矢量抗锯齿字形时，字体 Glyph 缓存极易耗尽内存导致系统 OOM 崩溃；
- **现代网络协议与 CA 证书缺失**：设备自带的 OpenSSL 与根证书严重老化，访问现代 HTTPS API（如天气接口）经常遭遇 TLS 握手失败；
- **功耗与发热**：设备端频繁进行复杂图像布局计算和网络握手，会导致电池迅速耗尽。

**当前正式架构（C/S 解耦）**：
- **主机端 (Windows 11 / Linux / macOS Server)**：7×24 小时常驻执行 Go 渲染服务。负责全量数据抓取（Open-Meteo 天气预报、空气质量、农历节气、名言）、Freetype 高清抗锯齿矢量渲染、布局计算、90°/270° 旋转、灰度像素量化，并提供内置 Web 设置与可视化预览页面。
- **Kindle 端 (Client)**：纯 Shell 脚本客户端（`sync-screen.sh`）。内存开销 < 1MB，零依赖外部工具链，仅通过局域网 HTTP 定时拉取 主机服务端渲染好的 758×1024 8-bit 灰度 PNG，并调用 Kindle 硬件原生 `eips` 命令刷屏显示。彻底消除 OOM 与崩溃死机风险。

## 2. 主机服务端设计

### 2.1 模块与布局引擎 (`internal/dashboard/`)
- **同一套几何计算**：正式渲染与 WebUI `/api/layout` 共享完全一致的模块边界与文本测量逻辑，杜绝浏览器端硬编码尺寸产生的偏差。
- **模块独立化**：
  - `Header`：时钟时间（支持 Bebas Neue、JetBrains Mono、Playfair、Montserrat、Noto 等多款高质感字体切换与位置微调）、公历日期、星期。
  - `Lunar`：精准农历推算、生肖年份、天干地支纪年、二十四节气。
  - `Weather`：当前温度、气象图标、当天温差范围、未来三天逐日天气预报、降水概率。
  - `BottomRight`：支持多模式切换（太阳光照轨迹、空气质量指数与级别、古诗词/名人格言等）。
  - `Footer`：数据更新时刻、Wi-Fi 状态、Kindle 上报电池电量与充电状态指示。

### 2.2 灰度与显示输出 (`internal/display/`)
- Kindle PW2 屏幕原生物理分辨率为 758×1024。
- 横放阅读时，画布初始尺寸为 1024×758（横版）。
- 渲染完成后，根据用户配置的 `rotate` 参数（90 或 270）进行像素级旋转，转换回 758×1024。
- **灰度量化**：输出强制转为 Go 标准库的 `*image.Gray`（8-bit 灰度格式）。
  > **关键约束**：Kindle 的 `eips` 工具对 24-bit RGB PNG 存在错误解码 Bug，会导致图像横向拉伸变形。使用标准灰度 PNG 可获得完美的 1:1 像素映射与极高的刷新速度。

### 2.3 Web 设置系统与原子配置更新 (`internal/server/`, `web/`)
- 提供优雅易用的单页管理控制台（WebUI）。
- 支持模块拖拽调整、字体选择、偏移微调、背光计划设置、实时效果预览。
- 服务端校验合法性后通过原子写入（临时文件写入 + 重命名替换）保存，杜绝并发写入损坏配置文件的风险。

## 3. Kindle 客户端设计

Kindle 客户端运行在已越狱的 PW2 设备上，位于 `/mnt/us/kdash/`，由轻量 Shell 脚本组成。

### 3.1 运行机制与低功耗
1. **分钟级整点对齐**：
   - 客户端根据系统时钟计算距下一分钟 00 秒的毫秒/秒级差值（`calc_next_minute_delay`），执行精准睡眠，确保日历时钟切换与现实时间完全吻合。
2. **防休眠与状态栏控制**：
   - 启动时通过 `lipc-set-prop com.lab126.powerd preventScreenSaver 1` 阻止 Kindle 进入待机锁屏。
   - 通过 Pillow IPC 隐藏顶部原生状态栏，释放完整屏幕显示面积。
   - 禁用 Wi-Fi 芯片的休眠省电策略（`iwconfig wlan0 power off`），确保长连接与拉取不丢包。
3. **内容变动比对 (SHA/CMP) 防频闪**：
   - 每次拉取新图片到 `/var/tmp/screen_new.png`。
   - 使用 `cmp -s` 对比新旧图片。若内容无变化，不触发 `eips` 刷新，降低墨水屏刷新损耗与电量消耗。
4. **容错与重试机制**：
   - 网络请求失败或服务端离线时，保持当前屏幕画面不闪烁。
   - `eips -g` 执行失败时保留旧图片并记录日志，绝不报告虚假成功，下次循环自动重试。
5. **硬件背光管理 (Frontlight Policy)**：
   - 支持 3 种工作模式：
     - `schedule`：定时计划（白天开启指定亮度，如 10；夜间自动彻底关闭为 0，柔和护眼且节能）；
     - `off`：全天 24 小时保持 0 亮度，极度省电；
     - `on`：固定常亮。
   - 写入 powerd IPC 的同时直接写入硬件驱动 `/sys/devices/system/fl_tps6116x/fl_tps6116x0/fl_intensity`，突破系统最低亮度为 1 的限制，实现真正的 0 亮度彻底关闭。

### 3.2 优雅退出与主页恢复
- 当通过 KUAL 菜单或命令行执行停止时：
  1. 向客户端发送 `SIGTERM` 信号；
  2. 触发恢复流程（`restore.sh`）：
     - 恢复 Wi-Fi 功耗管理；
     - 恢复 Kindle 原生屏保待机机制；
     - 恢复 Pillow 原生状态栏显示；
     - 切换回原生图书主页（`app://com.lab126.booklet.home`）；
     - 将启动时备份的 `/dev/fb0` 画面完整写回，避免局部残留；
     - 执行硬件全刷 `eips -s w=758,h=1024 -f`。

## 4. 安全与运维通道

1. **Wi-Fi SSH 端口 2222**：
   - 利用 KOReader 自带的 dropbear 搭建独立维护通道。
   - 避免直接开启 USBNetwork 的开机 auto 导致系统启动卡死在进度条。
   - 仅使用公钥认证（Mac 端 `~/.ssh/kdash_key`）。
2. **KUAL 菜单扩展集成**：
   - 提供全功能菜单：启动、刷新、重启、停止、状态查询、背光切换、自启安装与紧急恢复。
3. **管理接口鉴权**：
   - 图片和预览使用 HTTP 只读接口；配置保存、SSH 刷新、前光切换等修改操作统一使用 POST/PUT 与 `X-KDash-Token`。
   - 空令牌仅允许携带 `X-KDash-Client: kdash` 的本机回环请求完成首次设置，防止跨站表单；来自局域网的管理写操作必须配置随机令牌。
   - `KDASH_SETTINGS_TOKEN` 只存在于运行时，配置文件使用独立令牌字段，避免环境秘密在保存时落盘。
4. **主机服务生命周期**：
   - Linux 使用 systemd，macOS 使用当前用户 LaunchAgent，Windows 使用当前用户登录计划任务。
   - 三类启动方式均只传 `-config`，监听地址由配置文件决定；Windows 登录任务不等于未登录运行的 SCM 服务。
   - 本机停止脚本可调用受鉴权的 `/api/shutdown`，由 HTTP Server 执行优雅关闭。
